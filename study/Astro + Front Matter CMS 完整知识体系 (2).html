💻

VS Code — 你的"开发驾驶舱"

微软出品的代码编辑器，通过插件生态可以变成完整的 IDE。它是你整个工作流的起点和操作中心——写代码、管理文件、运行终端、操作 Git 全在这里完成。

类比：就像汽车的驾驶舱——方向盘（编辑器）、仪表盘（终端）、导航（Git面板）、收音机（插件）都集成在一起，你只需专注开车（写内容）。
🚀

Astro — 静态网站"排版印刷机"

一个专注于内容驱动型网站的现代前端框架。核心理念是 "Islands Architecture"（孤岛架构）：默认生成零 JS 的纯 HTML，只在需要交互的地方才加载 JS，速度极快。

支持 .astro / .md / .mdx 文件，可混用 React、Vue、Svelte 组件。

类比：就像出版社的排版工厂——你给它原材料（Markdown文章），它帮你排版成精美的HTML页面，发给全世界读者。
📋

Front Matter CMS — VS Code 内置的"编辑部管理系统" ⭐ 核心主角

Front Matter CMS 是一个 VS Code 插件，它把你的 VS Code 变成一个功能完整的 内容管理系统（CMS）。 它读取你 Markdown 文件顶部的 frontmatter（YAML元数据），并提供图形化界面来管理所有文章的元数据（标题、日期、标签、封面图、草稿状态等）， 无需手动编辑 YAML，还提供文章列表、媒体库、SEO 预览等功能。

📝 Frontmatter 是什么？
Markdown 文件顶部用 --- 包裹的 YAML 数据块，存储文章的元信息（标题、日期、标签等）
🖥️ CMS 是什么？
Content Management System，内容管理系统，让你用图形界面管理内容，而不是手动编辑代码文件
🔗 两者结合？
Front Matter CMS = 读取 Markdown 的 frontmatter，提供图形化界面，让你像用 WordPress 一样管理静态博客
类比：就像杂志社的编辑部系统——记者（你）写完稿件后，编辑部系统帮你管理所有稿件的状态（已发布/草稿）、分类、封面图、发布日期，一目了然，不用翻文件夹找稿子。
🐙

GitHub — 代码的"云端稿件仓库"

基于 Git 的代码托管平台。不仅保存代码历史，还是触发自动部署的信号源——每次 git push，Cloudflare 收到通知，自动拉取代码重新构建网站。

类比：就像出版社的稿件仓库——每次修改都有记录（版本控制），快递员（Cloudflare）随时来取货发货，而且永远不会丢稿。
☁️

Cloudflare Pages — 全球CDN"发行渠道"

静态网站托管服务，连接 GitHub 仓库，自动构建并部署到全球 300+ 个 CDN 节点。完全免费，支持自定义域名、HTTPS、边缘函数。

类比：就像全球连锁便利店——你的杂志被复制到全球300个城市，读者从最近的城市取货，速度极快，而且你不用管物流。

📝 Frontmatter 语法详解（Front Matter CMS 管理的核心对象）

src/content/blog/my-post.md 
---  ← Frontmatter 开始标记
title: "我的第一篇博客"
description: "关于Astro的入门文章"
pubDate: 2024-01-15
author: "张三"
tags:
  - astro
  - 前端
heroImage: "/images/cover.jpg"
draft: false
---  ← Frontmatter 结束标记

为什么选择这套技术栈？

理解每个工具解决了什么痛点，才能真正用好它

⚡

为什么用 Astro？

  • 默认生成纯 HTML，加载极快（Core Web Vitals 高分）
  • 内置 Markdown 支持，写博客超方便
  • 可混用 React/Vue，不锁定技术栈
  • 内容集合（Content Collections）批量管理文章
  • SEO 友好，适合内容型网站
类比：传统框架像"全功能豪华SUV"，Astro 像"轻量电动自行车"——去买菜不需要开坦克。
🖥️

为什么用 Front Matter CMS？

  • 不需要离开 VS Code，一站式工作
  • 图形化管理 frontmatter，不怕写错 YAML
  • 内置媒体库，图片管理方便
  • 文章列表视图，内容一览无余
  • 支持自定义字段类型，灵活扩展
  • 完全本地，无需订阅费用
类比：没有它就像用记事本管理100篇文章的元数据；有了它就像有了 Notion 数据库——一行一篇，清晰高效。
🔄

为什么用 GitHub？

  • 版本控制：每次改动有记录，随时回滚
  • 触发部署：push = 自动更新网站
  • 协作：多人开发不互相覆盖
  • 备份：代码永不丢失
  • CI/CD 集成：与 Cloudflare 深度连接
类比：就像 Google Docs 的历史记录，但专为代码设计，还能触发自动化流水线。
🌍

为什么用 Cloudflare Pages？

  • 完全免费（无限带宽、无限请求）
  • 全球 CDN，300+ 节点，访问极快
  • 自动 HTTPS，无需配置证书
  • 自定义域名，一键绑定
  • push 即部署，30-60秒上线
  • 支持预览部署（每个PR独立预览链接）
类比：相当于免费租了全球连锁超级服务器，运维全不用管。
🧩

为什么这套组合最优？

✓ 全程本地：不依赖任何在线 CMS 服务
✓ 完全免费：所有工具均有免费方案
✓ 自动化：写完推送，网站自动更新
✓ 高性能：静态页面 + CDN，速度极快
✓ 可扩展：随时接入 React/Vue 组件

理解项目目录结构

项目结构
my-blog/
├── src/
│   ├── content/              # 📝 内容层（Markdown文章）
│   │   ├── blog/

│   │   │   └── second-post.md
│   │   └── config.ts         # 定义 frontmatter 字段结构
│   ├── layouts/              # 🎨 页面布局模板
│   │   └── BlogPost.astro
│   ├── pages/                # 📄 路由（文件名=URL路径）
│   │   ├── index.astro       # → /
│   │   └── blog/
│   │       └── [...slug].astro # → /blog/文章名
│   └── components/           # 🧩 可复用组件
├── public/                   # 🖼️ 静态资源（图片等）
├── astro.config.mjs          # ⚙️ Astro 配置
├── frontmatter.json          # 📋 Front Matter CMS 配置（后面生成）
└── package.json
6

配置内容集合（定义 frontmatter 字段类型）

编辑 src/content/config.ts，用 Zod 定义字段结构：

src/content/config.ts
import { defineCollection, z } from 'astro:content';

const blog = defineCollection({
  type: 'content',
  schema: z.object({
    title:       z.string(),
    description: z.string(),
    pubDate:     z.coerce.date(),
    author:      z.string().optional(),
    tags:        z.array(z.string()).default([]),
    heroImage:   z.string().optional(),
    draft:       z.boolean().default(false),
  }),
});

export const collections = { blog };
